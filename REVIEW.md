# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–38) | Truncating minutes before checking `> 10` causes off-by-one bug. For example, 10 min 1 sec (`601s`) gives `minutes = int(601/60) = 10`. Since `10 > 10` is False, it returns 0 instead of 10. Also mixes naive/UTC punch-in with local shift start without IST timezone conversion. | Test with punch-in at `09:40:01` for shift `09:30`. Expected 10 late minutes, but returned 0. | Calculated total elapsed seconds against shift start in IST on the record date, verified `diff_sec > 600`, and returned `int(diff_sec // 60)`. |
| 2 | `compute_work_hours` (lines 40–42) | Python's built-in `round(..., 2)` uses banker's rounding (round-to-even) instead of standard half-up rounding. For example, `2.125` rounds to `2.12` instead of `2.13`. | Passing duration yielding `.125` hours; outputs `2.12` instead of `2.13` violating R4 and R8. | Implemented `round_half_up` using `decimal.Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 44–48) | Missing R3 requirement that overtime is counted only if `>= 30` minutes (it returned any positive minutes). Also fails for overnight shifts because it set `end` on `date_str` instead of the next day, resulting in ~24 hours overtime. | Employee with 5 minutes past shift end receives 5 overtime minutes instead of 0. Overnight shift employee receives >1400 overtime minutes. | Enforced threshold `diff_min if diff_min >= 30 else 0`, and advanced shift end date by +1 day when `shift_end <= shift_start`. |
| 4 | `create_employee` / Startup (lines 22, 77–86) | Check-then-insert (`find_one` then `insert_one`) is prone to race conditions under concurrency; duplicate employees can be created. No database unique index was created at startup. Also returns `created_at` as a Python datetime object instead of epoch milliseconds. | Sending two simultaneous `POST /employees` requests with identical `emp_code` results in duplicate documents instead of 409 Conflict. | Created a unique index on `emp_code` at startup and handled `DuplicateKeyError` to return HTTP 409. Formatted `created_at` as integer epoch milliseconds. |
| 5 | `list_employees` (lines 88–97) | Pagination formula `skip = page * page_size` skips the first page entirely when `page = 1` (skips 20 items instead of 0). Also, `total` counts the entire collection instead of filtered records `q`, and items were unsorted. | Calling `GET /employees?page=1` returned items 21–40. Filtering by department showed the global collection count. | Fixed skip formula to `(page - 1) * page_size`, updated count to `count_documents(q)`, added `.sort("emp_code", 1)`, and formatted epoch milliseconds. |
| 6 | `punch_in` (lines 99–123) | If employee does not exist, `emp["shift_start"]` raises an unhandled `TypeError` (HTTP 500) instead of HTTP 404. Also check-then-insert is not race-safe for concurrent punch-ins. | `POST /attendance/punch-in` with non-existent `emp_code` returned 500 Internal Server Error. Concurrent punch-ins create duplicate day records. | Added explicit 404 check if employee not found. Enforced compound unique index `{"emp_code": 1, "date": 1}` and caught `DuplicateKeyError` to return 409. |
| 7 | `punch_in` (lines 102–104) | Determines attendance date using local server time (`ts.date().isoformat()`), ignoring IST timezone (R1) and overnight shift rules where punch-in before shift end belongs to the previous calendar day. | Punch-in at 05:30 IST for a 22:00–06:00 overnight shift was tagged with today's date instead of yesterday's shift start date. | Implemented `get_attendance_date` with IST conversion and overnight shift previous-day resolution per R1. |
| 8 | `punch_in` & schemas (lines 118–121) | Injects an artificial `"id": str(res.inserted_id)` field into response, violating the OpenAPI schema which disallows document IDs and addresses records solely by `(emp_code, date)`. Also returned datetimes instead of epoch milliseconds. | Automated schema validator fails response due to extraneous `id` field and datetime serialization. | Removed `id` field injection and mapped all instant fields to integer epoch milliseconds per contract. |
| 9 | `list_attendance` (lines 124–152) | Calls `list(db.attendance_logs.find(q))` loading the entire collection into application memory, which collapses under 100k+ documents. Also secondary sort by `emp_code` was missing, and `date_from > date_to` did not return 422. | Memory exhaustion during performance testing on 100k documents. Incorrect tie-breaking order on identical dates. | Pushed pagination (`skip`/`limit`) and compound sorting (`[("date", -1), ("emp_code", 1)]`) directly down to MongoDB, backed by index. Added 422 validation for date ranges. |
| 10 | `health` (lines 72–75) | Returns static `{"status": "ok"}` without verifying database connectivity. Contract requires 503 if MongoDB does not answer. | Stopping MongoDB daemon still results in `GET /health` returning 200 OK. | Added `client.admin.command("ping")` probe inside a try/except block; returns HTTP 503 if database is unreachable. |
| 11 | Database Connection (line 22) | `MongoClient` initialized without `tz_aware=True`, leading to ambiguous naive datetime conversions when interacting with UTC BSON dates. | Naive datetimes returned from PyMongo led to timezone mismatch during local arithmetic. | Configured `tz_aware=True` on `MongoClient` and explicitly managed UTC/IST transitions at API boundaries. |
| 12 | Input Validation (lines 53–68) | Models lacked Pydantic constraints: `emp_code` regex, email regex, date format, shift validation (`shift_start != shift_end`), and epoch millisecond bounds (100000000000 to 4102444800000). | Supplying invalid strings or equal shift times resulted in invalid records or 500 errors instead of 422 Validation Error. | Added strict Pydantic Field regexes, validators, and range checks matching `openapi.yaml`. |

---

### Non-Defects Examined

1. **`IST = timezone(timedelta(hours=5, minutes=30))`**:
   Examined whether standard library `zoneinfo` or fixed `timedelta` offset should be used. Decided fixed offset `+05:30` is completely correct and optimal because Indian Standard Time does not observe Daylight Saving Time (DST).

2. **Absence of ObjectIds in API Models**:
   Examined the decision to not expose MongoDB `_id` on attendance or employee records. Confirmed this is intentional by design per `DATA_MODEL.md` (natural keys `emp_code` and `(emp_code, date)` are business identifiers).

3. **Treating Missing `history` and `half_day` as defaults**:
   Examined legacy records in `sample_data/` omitting `history` or `half_day`. Verified that treating missing fields as empty list (`[]`) and boolean `False` matches the contract specifications for backward compatibility.
